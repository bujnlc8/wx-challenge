# 整体逻辑审查依据

## 用户明确要求

- “保留现在的逻辑，重新设计一下这个小程序的UI”：普通挑战的计分、币奖励、等级、跳过、复活规则应保持。
- “单独答题，不应该沿用挑战模式，可以记分，但不是轮次的概念，也不存在复活，就是一次简单的答题”：每日一题及海报指定题目使用独立单题加载、提交、结果流程，不创建或继续挑战轮次。
- “从分享海报进去答题，应该是答完一道就停止的吧”：单题完成后停留结果，无自动续题。
- “每天答题的时候触发一次订阅”“一天最多触发一次”：开启提醒者有效提交时同步请求，按账号、模板与北京时间日期限制本机每日自动一次（不同运行版本共用，不随登录凭据更新重置）；拒绝、取消或失败当天不再自动弹。答题不等待许可与记账网络，许可面板不得消耗下一题时间。
- “每日挑战那里做一个类似github提交的图，做的题越多颜色越深”：使用真实有效作答数据，按北京时间聚合，明确启用前未记录历史，账户隔离。
- “二维码保存在数据库”“分版本保存”“颜色智能”：题目及小程序码按AppId、入口、题号、正式/体验/开发版及配色版本隔离保存，智能配色开启，重复获取使用真实已保存图片。
- “现在弹窗好像会穿透”：所有活动弹窗需拦截底层点击与背景滚动，长内容自身可滚动，短内容高度随内容自然变化，关闭一个重叠弹窗不得解锁另一个。
- 界面：三个Tab与答题顶部8px；练习为同款蓝卡+下方直接规则，无重复三项或底部宣传；菜单连续无分组、无分割，单色图标无背景，左名称15px与右说明13px分别统一；百科币菜单、等级在昵称下显示升级差额、退出在关于页。
- 海报：Logo圆角、题目正文完整、去掉指定宣传句；错题底栏日期+图标分享+纠错同行；分享码进入同一指定题，不回退随机题。

## 必须检查的逻辑边界

- 每次接受的提交不得因重试重复计分、发币、计活动或重复制造错题；服务端校验题目、选项、轮次归属及时间参数。
- 单题加载不创建答题/轮次记录；GET返回不透明题目版本，首次提交必须匹配用户看到的版本，版本失效且服务器明确未受理才允许重新加载；已接受的请求重放返回原结果。独立提交固定1000/0是本轮实施选择，不参与挑战榜或币奖励。错误答案进入错题集，挑战统计不能混入新单题。
- 指定题目不存在、下架、题库在加载与提交之间更新时，不能默默回答另一题或按用户未看到的选项判分。
- 请求失败、卸载、账号切换、晚到回调与原生订阅面板/海报返回，都不应污染其他账户或错误推进题目。
- 明确网络送达结果与数据库幂等；一次性通知未知发送结果不得重发。二维码JSON错误体不能存成图片，环境或身份不匹配不能复用。
- 新单题错题应在有效错题集可见；资料页冷/热缓存统计口径一致。历史练习错题缺来源为已知遗留数据边界，不猜测回填。
