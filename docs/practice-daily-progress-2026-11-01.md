# 练习进度与每日挑战完成态

练习首页在原蓝色介绍卡内显示服务端今日去重练习数、目标与奖励状态。`GET api/question/practice-progress` 仅在已有有效会话标识时读取，未登录显示“登录后记录今日进度”。每次返回页面重新读取并清空旧数值；离开、卸载、切换会话后的旧响应不写入当前页面。加载或接口错误不会显示为零，失败可点“重试”。

服务端 `answered_count` 原值直接显示，超过目标时仅进度条限制为 100%。`reward_received` 独立决定“百科币已到账”状态，即使进度缓存清理后计数为零，也保留零并如实显示已到账。达标尚未到账只说明“下次练习时自动发放奖励”，页面没有领取或发币操作。

每日挑战首卡改为日期与状态、紧凑横排插图、主按钮，答题记录热力图紧随其后。`GET api/daily-challenge/today` 的 `completed: true` 显示“今日已完成”和“再答一次”，按钮仍进入返回的原 `question_id`。旧接口没有 `completed` 时兼容为待答；存在但不是布尔值时显示可重试的错误。完成表示今日公共题已有提交，包含答错；重复作答的发币限制由服务端维持。热力图、提醒开关、一次性订阅以及每天一次自动提示逻辑保持现有实现。

验证：新增和更新测试覆盖真实页面方法的进度、异常、会话归属、返回刷新、完成字段及同题重答导航；认证、热力图与订阅回归通过。前端全套 `node --test tests/*.test.mjs` 为 267/267 通过。

使用独立 Chrome Target 对当前 WXML/WXSS 做源投影，在 320×460、375×600、430×720 视口检查无横向溢出、主按钮边界及固定练习入口；每日首卡下方答题记录从约 337px 处进入视野。此验证是浏览器对原生组件的投影，不代表微信真机验收。
