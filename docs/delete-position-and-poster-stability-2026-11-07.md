# 错题删除保位与应用海报首帧

用户明确要求删除成功后停留原地，避免重新从头浏览；另反馈分享小程序海报出现时闪烁。

## 错题删除

- 成功后按错题记录 id 局部移除卡片，保留其他对象、答案展开状态、已加载内容和页面位置，不自动清空列表或重读第一页。
- 服务端为 `uid/status` 过滤、`id DESC` 排序的偏移分页。前端维护已读取的服务端偏移；删除后回退偏移，下一次上拉允许重读边界页并按记录 id 去重，补齐缺口而不替换现有卡片。
- 同账号删除完成于隐藏期间，返回时局部移除对应卡片。账号切换、卸载不会接受旧写入对新列表的影响。删除写入与同账号读取互斥；用户主动下拉刷新会等待写入结束后读取新快照。
- 删除结果不确定时保留记录并提示核实，同时保守回退读取偏移，避免已在服务器提交的删除导致后续漏题。用户仍可手动下拉核实，不自动跳回首屏。
- 已确认删除的记录 id 用于过滤迟到响应；后端再次答错会插入新错题记录 id，因此不会屏蔽新错题。
- 已加载内容全被删除但仍可能有未读记录时继续读取；真正无剩余记录才显示空状态。

此约定替代上一轮“删除后重新读取第一页”的方案。

## 静态海报

- 先前 `openApp()` 发布了“可见、加载中、空图”，随后才发布静态图，产生中间状态；图片 `widthFix` 解码后又改变居中弹窗高度。
- 现在单次 `setData` 直接发布完整静态图片状态，为固定 900×1200 图片预留 3:4 空间并使用 `aspectFit`。保留正常入场动画，动态题目海报仍按原流程生成和展示。
- 继续使用内置成品，不增加后端请求或重新绘制。
